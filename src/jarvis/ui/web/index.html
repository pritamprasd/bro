Jarvis Mark 1: Tactical System Manual & User Guide
OFFICIAL OPERATING HANDBOOK

1. How Jarvis Works: Multi-Tier ReAct Architecture

Jarvis Mark 1 operates on an asynchronous Perception-Reasoning-Action (ReAct) cognitive loop optimized specifically for Linux X11 workstations with local NVIDIA RTX hardware.

[User Input] (Voice / Web HUD / Alt+J Spotlight / Telegram / CLI) │ ▼ [Tier-0 Instant Router: Llama 3.2 3B] (<100ms intent classification) │ ├── If Conversation ──> Direct Assistant Voice Reply (Iron Man JARVIS) │ └── If Complex Task ──> [Tier-1 Logic: Gemma 4 12B] (Pinned in VRAM) │ ├── Visual Inspection ──> [Qwen2.5-VL 7B] ├── High-Stakes Action? ──> [Approval Overlay] └── Actuators: ├── Desktop GUI (mss + pyautogui) ├── Everyday Browser (Chrome CDP :9222) ├── Sandboxed Web (Playwright) └── Python Runner (Data/Telegram)

Runtime Processes:

When running jarvis start, a master Process Supervisor manages two background daemons:

  • ui_server (FastAPI + Uvicorn on :8765): Powers this Stark HUD dashboard, WebSocket live streaming, telemetry polling, and audit storage.
  • worker daemon: Listens for the global Alt + J desktop hotkey, polls the Telegram bot, and triggers proactive sentinel watchdogs.

2. Lifecycle Management: Startup, Status & Kill-Switch

Jarvis features a centralized supervisor with PID file tracking in ~/.jarvis/supervisor.pid.

Starting Jarvis:

Starts all background components (Web HUD, Spotlight Bar, Telegram Bot, Watchdogs):

uv run jarvis start

Checking Health & Status:

uv run jarvis status

Master Kill-Switch (Clean Termination):

Immediately sends SIGTERM signals to all child daemons and removes PID files cleanly:

  • Via CLI: uv run jarvis stop
  • Via Web HUD: Click the red 🛑 KILL SWITCH button in the header bar.
  • Via Telegram: Send /kill to your remote bot.

3. Four Communication Modalities

You can interact with Jarvis effortlessly through four distinct user interfaces:

A. Web HUD Dashboard (Voice Microphone)

Click the Microphone Button in the Mission Control bar. Speak your command (e.g. "Hello Jarvis", "Inspect active screen and summarize"). The Web Speech API transcribes your speech in real time and submits the task automatically.

B. Desktop Spotlight Bar (Alt + J)

Press Alt + J from any application (VS Code, terminal, browser). A floating translucent HUD appears in the center of your screen. It automatically captures your active window title and clipboard text. Type your goal and press Enter.

C. Terminal CLI & Voice

# Direct CLI Task: uv run jarvis run "Summarize latest downloads" -f ~/Downloads/report.pdf # Dedicated Voice Listening Mode (faster-whisper on RTX 3060): uv run jarvis voice

D. Telegram Remote Control from Phone

Message your private bot anywhere while on the go:

  • /run <goal>: Runs an autonomous task on your workstation and replies with the outcome.
  • /status: Returns real-time CPU, RAM, GPU temperature, and VRAM telemetry.
  • /screen: Captures a high-resolution screenshot of your desktop and sends the image.
  • /kill: Emergency kill-switch.

4. Conversational Modes & Voice Reply Controls

Jarvis Mark 1 speaks with the Iron Man British AI butler persona (en-GB-RyanNeural, pitch -4Hz, rate +2%).

Web UI Conversation Modes:

You can effortlessly switch between three conversational modalities using the glowing header pills or below:

  • Audio Only: Hands-free, voice-first interaction! Activates the animated Iron Man Arc Reactor Voice HUD with soundwave equalizers. With Hands-Free Continuous Loop enabled, the microphone automatically re-arms after Jarvis speaks back, giving you a fluid spoken dialogue.
  • Audio + Chat (Default): The best of both worlds. Full real-time terminal streaming and thought transparency, combined with spoken voice replies whenever Jarvis responds.
  • Chat Only: Silent mode. All voice playback is muted. Interactions are logged and delivered strictly as formatted text in the terminal and chat console.

Conversational Intent:

When you say "Hello", "Good morning", or ask casual questions, the Tier-0 router flags this as CONVERSATION and Jarvis speaks back directly.

Configuration in config.yaml:

# Conversation mode on Web UI: "audio_only", "audio+chat", or "chat_only" conversation_mode: "audio+chat" voice: enabled: true voice_reply_on_chat: true # Speak answers to conversational chat always_voice_response: false # Speak answers to all tasks

5. Daily Brief: On-Demand & Workstation Status

The Daily Brief provides a spoken and visual summary of workstation health, memory sync, and greeting.

Triggering On-Demand:

  • Via CLI: uv run jarvis brief
  • Via Web HUD: Click the yellow Daily brief button in the top navigation or quick action tile.

Auto-Start Disabled by Default:

To avoid unwanted interruptions, scheduled morning briefings are turned off by default. To enable automatic briefings at 08:30 AM, set watchdogs.cron.enabled: true in config.yaml.

6. Resource Attachments & On-Demand Missing File Prompting

Jarvis can leverage local files, CSV datasets, PDF documents, or reference images to accomplish tasks.

Attaching Files Upfront:

  • In Web HUD: Click Attach File / Resource or drop files into the resource bar. Each attached file is indexed and sent with your task.
  • In CLI: Use the -f or --file flag:
    uv run jarvis run "Analyze quarterly revenue" -f /path/to/q3.csv

On-Demand Missing File Prompting:

If you ask Jarvis to perform a task requiring a file that was not provided (e.g. "Process the customer dataset"), Jarvis will detect this during reasoning and invoke request_file:

  • An interactive alert modal appears on the Web HUD (or a Rich prompt in terminal).
  • You can either Upload / Drop the file, or enter an Absolute Local Path (e.g. /home/pritam/data.csv).
  • Click Supply File & Continue. Jarvis resumes execution immediately with the supplied file!
  • If the file is unavailable, click File Unavailable / Skip and Jarvis will continue with an alternative strategy.

7. Selecting Local RTX 3060 Models from Ollama

Jarvis Mark 1 is 100% local by default, running without cloud billing or API keys on your RTX 3060 (12 GB VRAM).

Subsystem Models:

  • 1. Text & Reasoning: gemma4:12b — handles complex ReAct planning and multi-step tool orchestration.
  • 2. Vision UI Grounding: qwen2.5vl:7b — inspects 1080p desktop screenshots and calculates UI click coordinates.
  • 3. Tier-0 Fast Classifier: llama3.2:3b — sub-100ms classifier to route intents instantly.

To switch models, navigate to the Model Selection tab, pick your preferred models from the dynamic Ollama list, and click Save Model Preferences.

8. Desktop & Web Automation Capabilities

Vision-Based Computer Use:

Jarvis captures your physical X11 display (1920×1080) in <20ms using mss, calculates element coordinates using qwen2.5vl:7b, and moves the mouse and types via pyautogui.

Dual Browser Strategy:

  • Everyday Chrome / Brave (CDP Mode): Click Attach Chrome (CDP :9222). Jarvis connects directly to your active browser session with full access to your logged-in GitHub, Gmail, or Jira accounts without 2FA or CAPTCHAs.
  • Isolated Sandbox: For disposable or private web tasks, Jarvis spins up an isolated Playwright browser with its own sandbox directory in ~/.jarvis/browser_data.

Python Runner:

Executes safe local Python scripts for heavy data crunching, math, and Telegram messaging via requests. Keyring credentials are auto-injected as environment variables.

"Watch & Learn" Macro Compiler:

When you demonstrate a multi-step desktop workflow, Jarvis compiles the action sequence into a deterministic Python script in ~/.jarvis/memory/workflows/. Future executions run in <0.5s without model overhead.

9. Safety Gatekeeper & Approval Overlay

By default, autonomous_mode: false:

  • Any high-stakes action (e.g. destructive commands like rm -rf, sudo, database drops, payments, sending emails) automatically pauses execution.
  • A floating translucent Approval Overlay appears on your X11 display.
  • Press Enter to authorize or Esc to reject.
  • To enable full unattended autonomy, launch tasks with --autonomous or toggle in config.yaml.

10. Audit Trail, Session Replay & KPI Analytics

Every mission is recorded in ~/.jarvis/runs/ with metadata, step observations, and full-resolution screenshot filmstrips.

  • Visual Charts: Inspect the SVG Actuator Donut Chart and Latency Trend Bar Chart in the Audit & History tab.
  • Step Lightbox: Click any step screenshot to open the 1080p full-resolution lightbox viewer.
  • Markdown Export: Click Export Markdown Report to save a clean summary of any mission.

11. System Failure Alerts, Timeouts & Error Logs

Jarvis tracks all exceptions, model connection failures, step timeouts, and sentinel warnings in memory and on disk.

  • Click System Alerts to view active warnings with timestamps, classifications, and stack traces.
  • If errors occur, an alert badge appears in the top navigation bar.
  • Click Clear Error History once issues are addressed.

12. Lean Markdown Memory & Secure Keyring Vault

Lean Markdown Memory:

Stored as human-editable markdown files in ~/.jarvis/memory/:

  • preferences.md: Personal assistant preferences and rules.
  • system.md: Linux workstation hardware specifications.
  • contacts.md: Frequently contacted people and communication channels.
  • workflows/: Application recipes and compiled macros.

Secure Vault (Linux Keyring):

# Store credentials in Linux Keyring: uv run jarvis vault set telegram_bot_token "YOUR_TOKEN" uv run jarvis vault set telegram_chat_id "YOUR_CHAT_ID" # List stored keys: uv run jarvis vault list

13. Visual Media: Diagrams, Charts & System Windows

Whenever Jarvis needs to present a diagram, chart, plot, or screenshot, it renders the visual using either an in-HUD dialog or a native X11 desktop system window.

Supported Visual Modalities:

  • Mermaid Diagrams: Architecture diagrams, flowcharts, sequence diagrams, and state machines are rendered interactively via Mermaid.js SVG engine.
  • SVG & Data Charts: Inline SVGs or generated data plots (matplotlib/seaborn) are displayed with crisp vector quality.
  • Screenshots & Images: High-resolution desktop captures, inspection crops, and local images with full-resolution zoom.

Dual Delivery Targets:

  • Web HUD Dialog Modal: Translucent Stark Industries HUD popup with interactive zoom, raw code viewer toggle, and instant clipboard copy.
  • Native X11 Desktop Window: Clean desktop window powered by Python Tkinter & Pillow with smooth image scaling and resolution tags.

Agent Action Syntax:

# Agent action syntax: Action: show_media Action Input: {"media_type": "diagram", "content": "graph TD; A-->B", "title": "Flow", "target": "both"}

14. Multi-Desktop & Display Perception Setup

On Linux X11 systems with multiple physical or virtual monitors, Jarvis allows you to designate which screen serves as the active perception canvas for mouse, keyboard, and visual grounding operations.

Multi-Monitor Topologies:

  • Display 0 (Combined Virtual Canvas): Captures all screens stitched together into one bounding box.
  • Display 1 (Physical Screen 1): The primary physical monitor (e.g. HDMI-1 at 1920×1080).
  • Display 2 (Physical Screen 2): Secondary physical monitor with automatic coordinate offset calibration.

How to Configure:

Switch displays anytime via the SCREEN dropdown in the persistent top header capsule, or visit the Main Desktop tab to inspect high-resolution live screen previews.

# CLI or Config: # ~/.jarvis/config.yaml desktop: screen_index: 1 # 1=Primary, 2=Secondary, 0=Combined Canvas

15. Terminal Typography & Interactive Font Scaler

The Command Center terminal console is engineered with a high-contrast obsidian deck, JetBrains Mono font, and dynamic size scaling to ensure maximum scannability on all Linux X11 display scaling profiles.

Key Readability Enhancements:

  • Custom Font Scaling: Use [A-] and [A+] in the controls bar beneath the console to scale text between 12px and 26px. Click [Reset] to return to 15px.
  • Permanent Persistence: Your preferred font size is saved directly to your browser's localStorage (jarvis_terminal_font_size) and restored automatically.
  • Relaxed Line Height & Letter Spacing: 1.7 line height and 0.022em letter spacing eliminate cramped or overlapping code blocks.
  • Translucent Badge Accents: Color-coded left border badges and subtle tints separate thoughts (sky blue), actions (warm amber), steps (neon cyan), results (emerald green), and errors (crimson).
